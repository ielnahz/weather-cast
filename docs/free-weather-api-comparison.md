> 调研时间：2026-11-09

## 二、详细评估

### 1. Open-Meteo（⭐ 本项目首选）

- **官网**: https://open-meteo.com/
- **GitHub**: https://github.com/open-meteo/open-meteo
- **Key**: **完全不需要**，直接调用
- **免费额度**: 无明确上限，官方建议每日不超过 ~10,000 次
- **支持能力**:
  - 当前天气（温度、湿度、风速、天气代码等）
  - 逐小时预报
  - 多日预报（最多 16 天）
  - 内置地理编码 API（搜索城市名 → 经纬度）
- **数据来源**: 国家气象服务的高分辨率开放数据（1-11km）
- **返回格式**: JSON
- **优点**:
  - 零配置，面试官 clone 项目即可运行，无需注册任何 Key
  - 地理编码 + 天气数据一站式解决
  - 开源、非商业用途完全免费
  - 字段可通过参数自定义（`current=temperature_2m,relative_humidity_2m,...`）
- **缺点**:
  - 天气代码（weather_code）是 WMO 编码，需自行映射为人类可读描述
  - 不含空气质量数据
  - 无历史数据

**地理编码 API 示例**:
```
https://geocoding-api.open-meteo.com/v1/search?name=Beijing&count=5&language=zh
```

**天气 API 示例**:
```
https://api.open-meteo.com/v1/forecast?latitude=39.9&longitude=116.4&current=temperature_2m,relative_humidity_2m,wind_speed_10m,weather_code&daily=weather_code,temperature_2m_max,temperature_2m_min&timezone=auto
```

---

### 2. OpenWeatherMap（备选）

- **官网**: https://openweathermap.org/api
- **Key**: 需要，免费注册
- **免费额度**: 60次/分钟
- **支持能力**:
  - 当前天气
  - 5天/3小时间隔预报
  - One Call API 4.0（聚合当前+预报+历史）
  - 空气污染、太阳辐射等
  - 46年历史数据
- **优点**: 字段规范，社区文档最丰富，教程最多
- **缺点**: 需要注册 Key，面试官需自行申请才能运行

---

### 3. WeatherAPI.com（备选）

- **官网**: https://www.weatherapi.com/
- **Key**: 需要，免费注册
- **免费额度**: 100,000次/月（最慷慨）
- **支持能力**:
  - 实时天气
  - 14天预报 + 15分钟精度
  - 历史数据（从2010起）
  - 海洋、空气质量、花粉、警报、天文数据
  - 内置地理编码
  - 多语言
- **优点**: 功能最全，免费额度最大，内置搜索
- **缺点**: 需要注册 Key

---

### 4. wttr.in（轻量方案）

- **官网**: https://wttr.in
- **Key**: 不需要
- **支持能力**: 当前天气 + 预报，支持 JSON（`?format=j1`）和终端文本
- **优点**: 零配置，适合命令行
- **缺点**: 字段精简，不适合结构化展示，有频率限制

---

### 5. 万维易源（国内方案）

- **Key**: 需要（免费 appKey）
- **支持能力**: 全球经纬度查询，含天气 + 空气质量
- **优点**: 国内服务稳定，含 AQI 等字段
- **缺点**: 需注册，国内服务商

---

### 6. sojson（国内轻量）

- **Key**: 不需要
- **支持能力**: 仅国内城市，按城市代码查询
- **优点**: 零配置，国内城市够用
- **缺点**: 无 SLA，仅国内，字段有限

## 三、本项目选型建议

### 主选：Open-Meteo

**理由**:
1. **零配置**——面试官 clone 后直接 `npm install && npm run dev` 即可运行，无需注册任何 API Key
2. **一站式**——地理编码 + 天气数据都有，不需要额外接入搜索 API
3. **免费且开源**——非商业用途无限制
4. **字段可定制**——通过参数指定需要的字段，减少无用数据传输（也体现了性能意识）

### 架构预留：可切换

在三层 API 架构的中层（adapter layer）预留 `OpenWeatherMapAdapter`，README 中说明：
> 默认使用 Open-Meteo（零配置），架构上支持切换至 OpenWeatherMap / WeatherAPI.com，只需新增 Adapter 实现。

这样既展示了对 API 选型的思考，也体现了架构的可扩展性——这正是"设计取舍"的体现。
